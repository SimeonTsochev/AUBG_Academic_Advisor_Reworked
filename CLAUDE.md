# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AUBG Academic Advisor: a FastAPI backend (`backend/`) that builds a multi-semester degree plan from the AUBG catalog, and a Vite + React + TypeScript frontend (`frontend/`, originally exported from Figma) that lets a student pick majors/minors, import a transcript, and edit the plan.

## Commands

Backend (run from `backend/`). Use Python 3.12: the pinned `pydantic==2.11.7` has no wheel for 3.14. On Windows `py install 3.12-64` installs it without admin rights.

```bash
py -3.12 -m venv .venv && .venv\Scripts\activate      # Windows; python3.12 -m venv .venv elsewhere
pip install -r requirements.txt -r requirements-dev.txt
uvicorn main:app --reload --port 8000
```

Tests are `unittest` classes in `backend/tests/`; pytest (with pytest-randomly, so order is shuffled every run) runs them too.

```bash
python -m pytest tests -q                                             # all, random order
python -m pytest tests -q -p no:randomly                              # fixed order
python -m pytest tests/test_real_catalog_scenarios.py -k corequisite  # one test
python -m unittest discover tests                                     # stdlib runner
python -m ruff check .                                                # lint (F rules, see ruff.toml)
```

Frontend (run from `frontend/`): `npm ci`, `npm run dev` (port 3000), `npm run typecheck` (`tsc --noEmit`), `npm test` (vitest, `src/**/*.test.ts`), `npm run build` (outputs to `build/`). The API base URL comes from `VITE_API_BASE` in `frontend/.env`. The React plugin is `@vitejs/plugin-react`, not the SWC one: Windows Application Control on the dev machine blocks the unsigned `@swc/core` binary.

Everything at once, as CI and the pre-push hook do: `backend/.venv/Scripts/python scripts/check.py` from the repo root (`git config core.hooksPath .githooks` enables the hook). `check.py` exits early if `npm` is not on PATH; Node is at `C:\Program Files\nodejs` on the dev machine, and shells or editors started before it was installed don't see it, so prepend it to PATH rather than skipping the hook.

Rebuild the catalog JSON artifacts after changing the source PDF/Excel or the parsers (runtime never parses the PDF/Excel):

```bash
python scripts/build_catalog_artifacts.py      # writes data/excel_catalog.json + data/pdf_requirements.json
python scripts/compare_catalog_mismatch.py     # writes data/catalog_mismatch.json (--stdout-only to preview)
```

## Architecture

### Catalog data pipeline (offline → runtime)
- Sources: `backend/AY-2026-27-2nd-ed.pdf` (program requirements, prereqs, GenEd rules) and `backend/course_catalog 031926.xlsx` (course list, credits, GenEd tags, elective tags, and the Fall 2026 schedule as `semester_availability`).
- `catalog_parser.py` (PDF) and `excel_course_catalog.py` / `excel_catalog.py` (Excel) are used only by the build scripts via `catalog_artifacts.py`.
- At runtime `catalog_cache.getCatalogCache()` loads the JSON artifacts from `backend/data/` once, applies `data/policy_overrides.json`, attaches the Excel catalog and mismatch snapshot, and exposes a single `default_catalog` dict. Fix wrong catalog data in `policy_overrides.json` rather than in engine code: per-course `course_meta` patches (a shallow `dict.update`; e.g. ENG 1000's `coreq_codes`, 0-credit courses) and `degree_total_credits` (120, AY 2026-27 catalog p.72). `course_renumbering` maps an old course code to its current one (COS 4060 -> COS 3060); `generate_plan` translates completed, in-progress and retake codes through it, so a transcript with the old number satisfies the new requirement. Policy credits win over Excel and PDF values. The same file corrects programs the PDF parser gets wrong (`majors` / `minors`: `required_courses` and `elective_requirements`, each with a `source` note citing the catalog page) and restores prerequisites for course rows the parser missed; each major also carries `diploma` (`dual`/`single`, p.72). `policy_overrides.json` is edited by hand: a course list repeated across rules is named once in `course_groups` and written as `{"group": name}` inside `courses_in` / `except`, which `catalog_artifacts.expand_course_groups` expands when the policy loads (an unknown name fails loudly). Programs (majors and minors) can carry, each citing its catalog page:
  - `options`, choices the student makes: CS and IS concentrations (pp.87, 96), the European Studies language (p.90), the Modern Languages and Cultures language focus for the major and the minor (pp.102, 124). Each choice has course `blocks` with a `role` (`elective`: counts as the program's electives, tagged `concentration`; `required`: the program's own courses once chosen; `collateral`: outside the program's credits, not double-counted, not in GPA-in-major, tracked in `category_progress.options`), optional `prefer` courses for the planner, and its own `elective_rules`/`elective_pool`. `generate_plan(program_options={program: [choices]})` keys choices by program name (nobody has the same program as major and minor); a required option without a choice is a validation error.
  - `elective_rules` (`elective_rules.py`): the catalog's elective sub-rules as `at_least`/`at_most`/`at_least_in_one_group` over course sets (`courses_in`, catalog wildcards in `patterns` such as `ENG 3[4-9]NN` and `COS L[1-2]NN`, `prefixes`, `exclude_prefixes`, `except`, `min_level`, `and_excel_tags`, `any_of`), parsed into `ElectiveRule` / `CourseSet`: a set's members are its codes, patterns, prefixes and `any_of` sets (a union; no members means every course) and its filters apply to the whole set. `elective_progress.py` evaluates them on completed (including topics courses outside the planning pool) and planned courses: caps limit what counts, unmet minimums raise `remaining`, and each rule comes back in `elective_progress[].rules` for the elective card. `elective_pool` adds eligible courses, `elective_excluded` never counts (POS 4092, EUR 4092), `elective_pool_only` counts nothing but the rules' and pools' courses (the MLC focuses), `max_transfer_elective_credits` caps manual credits (18 by default, p.68).
  - `placement_waivers` (C++ COS 1020, C# INF 1030, the MLC placement courses): a waived course satisfies its requirement with no credits and, with `replace_with_elective`, adds its credits to the program's electives; the request sends `placement_waivers`. `generate_plan` also waives MAT 1000 / ENG 1000 (`PLACEMENT_FOUNDATION_COURSES`) itself when the student passed or is taking a course that needs one or is its co-requisite (`_foundation_courses_moved_past`: MAT 1003 "MAT 1000 or equivalent", ENG 1001 with ENG 1000), exactly as if `waived_mat1000` / `waived_eng1000` were set; waived courses come back in the response's `completed_courses`, which the frontend counts as satisfied prerequisites.
  - `grade_rules` (`academic_record.py`: declaring Business needs 2.500 in its first five courses, the JMC capstone 3.250 in the major, SDM 3001 a 3.500 GPA, Finance minor courses a C or higher) and `sequence_rules` (the Literature minor's ENG 2010 before 3000-level ENG): `degree_engine.program_sequence_rules` parses them into `SequenceRule`s, which the scheduler (`_eligible_for_term`) plans by and `graduation_checks.sequence_check` audits.
  `catalog_options.py` is the one reader of `options` and `placement_waivers`: it returns typed `ProgramOptions` / `OptionChoice` / `OptionBlock` / `PlacementWaiver` (roles resolved, codes normalized via `course_codes.py`), and the engine, elective progress, graduation checks, the API and the program pages all use it instead of the raw dicts. `/catalog/load-default` returns `program_info` (majors) and `minor_info` (minors) with the options and placement waivers. The frontend keeps choices in `selection.programOptions` and waivers in `selection.placementWaivers` (setup screen; `ProgramOptionPrompt` lets a saved plan add a missing required choice in place); `tests/test_catalog_corrections.py` checks every program's required plus elective credits against the catalog's printed total. A "Program Choice" block that means "N of these" states the count in its `rule_text` ("Two of ...") and leaves `courses_required` empty, with no course codes in the text, or the minor-proximity code counts it twice and the OR-detection splits it.
- The catalog dict shape (`courses`, `course_meta` with `prereq_codes`/`prereq_text`/`coreq_codes`, `majors`/`minors` with `required_courses` + `elective_requirements`, `foundation_courses`, `gen_ed.categories`/`gen_ed.rules`, `excel_catalog`, `degree_total_credits`) is what every engine function consumes, and what tests build by hand.

### Degree engine (`degree_engine.py`)
`generate_plan(...)` is the single entry point. Rough flow:
1. `build_requirement_slots` turns selected programs, GenEd rules and foundation courses into requirement slots (`fixed` course or `choice` among courses).
2. `select_courses_for_slots` picks a course per slot, preferring courses that satisfy several slots; prerequisites of chosen courses are added.
3. `_schedule_courses` packs courses into terms (prereqs, standing, GenEd sequencing via `CATEGORY_PREREQS`, co-requisites together, credit caps); `balance_term_credits` pulls courses forward and tops up under-filled terms with `FREE ELECTIVE n` placeholders; `_rebalance_term_mix` swaps courses for variety but never moves foundation courses or co-requisite pairs; `_top_up_to_degree_total` adds placeholders until the plan reaches `degree_total_credits`. A term with in-progress courses is already registered: these planning steps see it as full (`registered_terms_full`) and add nothing to it, not even placeholders, while validation and the audit use its real credits and do not flag it as below the minimum load.
4. `_apply_plan_overrides` applies the user's edits (`overrides`: `add`/`remove`/`move`, matched by `instance_id` or code) and emits `OVERRIDE_*` warnings instead of failing. An instance id that is both removed and added: the remove wins (`OVERRIDE_CONFLICT`). Overrides are saved against an older plan, so they follow the plan when it changes: a term-scoped remove that misses follows a course that now appears exactly once elsewhere (`OVERRIDE_REMOVE_RELOCATED`), a missed `FREE ELECTIVE n` remove takes another placeholder in the same term, and adds/moves to terms before the plan start are dropped (`OVERRIDE_TERM_BEFORE_START`). When a reshuffled base plan leaves a semester over the limit after the edits, `_relieve_overloaded_terms` moves the planner's own courses (never the student's adds, moves or retakes, nor foundation courses or co-requisite pairs) to the next semester with room, taking a free-elective placeholder's place if needed (`OVERRIDE_COURSE_RELIEVED`): catalog corrections keep changing the base plan, and saved swaps must survive that.
5. `validate_plan` checks the schedule; then `generate_plan` builds one `PlanState` (`plan_state.py`: the final plan plus the student's completed, in-progress, waived and planned courses, grades and options, with derived `done`, `courses` and credit figures) and calls `plan_audit.audit_plan(state)`, which runs the graduation checks, elective progress, progress rows and GPA record below and returns their errors. New policy checks take the state rather than more parameters. `validate_plan` audits the final plan (requirement coverage re-matched against completed + planned courses, standing, co-requisites, credit limits, degree total); warning builders add `FOUNDATION_LATE`, `TERM_UNAVAILABLE`, `UNSCHEDULED_COURSE`, `PLAN_EXCEEDS_STANDARD_LENGTH`. Each planned course carries `requirements` (e.g. "Computer Science major: required course") and `unlocks` (dependents planned in a later term only). `graduation_checks.py` then adds the catalog's graduation rules that the slots cannot express (≥3 WICs besides ENG 1001/1002, 60 AUBG credits, at most 3 retakes including `is_retake` override adds, double-counting limits of 3 between two majors and 2 otherwise) plus the internship and independent-study policies from `course_kinds.py` (at most 3 academic internship credits; at most 2 independent studies a semester, 5 in all, each after 30 earned credits with a GPA of 3.100; pp.61, 63), to `validation_errors` and returns the details as `graduation_checks`; the dual-diploma rule (p.72) is only `graduation_checks.dual_diploma.ok`, which the frontend shows as a note (`DiplomaNote`), because a student may not have added the second major yet; the WIC check is skipped for catalogs without WIC flags, and the residency, course-load and independent-study rules apply only when the catalog sets `enforce_academic_policies` (`policy_overrides.json` does; the synthetic test catalogs don't). `academic_record.py` turns the request's `grades` ([{code, grade, term}], latest attempt wins) into `academic_record`: cumulative and per-term GPA (Dean's/President's List), GPA in each major (slot and elective courses, not collateral), the Latin honors outlook, and errors for GPA-in-major < 2.5, cumulative GPA < 2.0 and course loads above 17 (first-years, GPA < 3.3 or unknown), 19 (Dean's permission) or 22. A semester below `MIN_CREDITS_PER_TERM` (12, full-time status, catalog p.57) is an error, but the planner fills semesters to `PLANNING_MIN_CREDITS_PER_TERM` (14): keep the two apart, since changing what the planner fills to reshuffles every base plan and breaks the edits saved against it. There is no credit-load setting: the API always plans at `STANDARD_MAX_CREDITS_PER_TERM` (17, catalog p.65) and ignores the request's `max_credits_per_semester`; `validate_plan` then only rejects more than 22 (with `enforce_academic_policies`) so the load rules above give the catalog's reasons. The frontend plans with 17 and lets the student add courses up to `academic_record.max_load` (19 with GPA ≥ 3.3).

Key rules:
- Standing is measured in earned credits (`_min_credits_for_course`): sophomore/junior/senior 27/57/87 (catalog p.47), "completion of N credits", declared major 27, 3000/4000-level 27/57. Earned credits include transfer (manual) credits and completed courses outside the planning pool, minus placement waivers.
- Term availability: the Excel data is a single-semester schedule. A course is "not offered" in a term only if that term has published data and the course is missing from it (`_offered_terms_if_unavailable`); other terms are unknown and allowed. `/catalog/load-default` sends each course's `semester_availability` from the engine's `_course_offered_terms` (`[]` = a schedule record that no published term lists; absent = no record), and the frontend blocks adding any course to a published term that does not list it (`utils/courseAvailability.ts`, `plan_add` with a target term), so the dialogs never offer a term the planner would refuse with `OVERRIDE_ADD_TERM_UNAVAILABLE`.
- Plans are capped at `MAX_PLAN_TERMS` (12) and never silently truncated.
- Program-specific rules (Computer Science, Creative Writing, Fine Arts and Economics minors, Business concentrations in `business_concentrations.py`, Textual Analysis GenEd sequencing) are hard-coded special cases inside the engine. Search for the program name before changing generic logic.
- Term labels are `"Fall YYYY"` / `"Spring YYYY"` (`_canonical_term_label`); overrides to anything else are rejected with `OVERRIDE_INVALID_TERM`.

### API (`main.py`)
Endpoints: `/catalog/load-default`, `/courses`, `/courses/search`, `/courses/{code}`, `/plan/generate`, `/plan/download.pdf` (`pdf_export.py`, reportlab), `/transcript/import` (PDF via pdfplumber, images via OCR) and `/transcript/import-text` (`transcript_import.py`), `/program-snapshots` (`snapshots_db.py`, Supabase). Request/response models are in `models.py` and mirrored by hand in `frontend/src/api.ts`; change both together (the type checker now catches drift on the frontend side).
- Plan endpoints are plain `def` (threadpool) because planning is CPU-bound; `/plan/generate` results are memoized in `PLAN_CACHE` (locked) keyed by the request JSON and the current term.
- `catalog_id` is effectively always the default catalog; `_ensure_catalog` binds any id to it.
- Env vars: `CORS_ORIGINS`, `CORS_ALLOW_ALL` (Vercel preview domains are always allowed), `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (snapshot endpoints return 503 without them).

### Frontend
`App.tsx` switches between `welcome` → `setup` (`AcademicSetupScreen`) → `advisor` (`MainAdvisorScreen`), and restores shared plans from `/p/<token>` snapshot links. "← Setup" hands the advisor's current snapshot payload and grades back to `App`, which pre-fills setup with them (`SetupPrefill`) and reopens the advisor with the same edits. `MainAdvisorScreen.tsx` is very large and holds most client state: plan overrides, retakes, transcript import, chosen electives (`swappedElectives`, with the "Swap elective" flow), and a debounced autosave that creates program snapshots. Every edit re-calls `/plan/generate` with the accumulated overrides; the backend is the source of truth for plan contents, and the semester cards show its `semester_plan` as returned (no client-side re-picking, padding or trimming). Edits the planner skipped or adjusted (`OVERRIDE_*` warnings) are shown by `components/advisor/SkippedEdits.tsx` via `utils/planWarnings.ts`. Transcript grades are private: setup collects them, `MainAdvisorScreen` keeps them in `localStorage` under the current share token (`hooks/usePrivateGrades.ts` over `utils/grades.ts`, moved to each new token) and sends them with `/plan/generate`, and they are never added to the snapshot payload, so a shared `/p/<token>` link does not reveal them. Pure, unit-tested helpers live in `src/utils/` (override edits in `planOverrides.ts`, availability, reasons, terms, retakes, OCR parsing); put new logic there rather than in the component. Self-contained component state goes in hooks under `src/hooks/` (`useProgramOptions`, `usePrivateGrades`), and setup-screen cards in `components/setup/`, next to the advisor's `components/advisor/`. `src/components/ui/` is generated shadcn/Radix UI.

### Public requirement pages (SEO)
`backend/program_pages.py` turns the planner's own requirement slots into `frontend/seo/programs.json` (`python scripts/build_program_pages_artifact.py`, also run by `build_catalog_artifacts.py`; `tests/test_program_pages.py` fails when the committed file is stale). After `vite build`, `frontend/scripts/generate-seo-pages.mjs` writes static HTML for `/majors`, `/minors`, `/majors/<slug>`, `/minors/<slug>` and `/general-education`, plus `404.html` and `sitemap.xml`, into `build/` (rendering lives in `scripts/seo-pages.mjs`, tested by `src/seo/seoPages.test.ts`). Pages also list each program's elective rules and options (concentrations, language focuses). Programs the planner cannot describe (the Self-Designed Major) are listed in `_SKIP_PROGRAMS` and get no page. `vercel.json` rewrites only `/p/:token` to the app, so unknown URLs are real 404s. Page links such as `/?major=Computer%20Science` preselect the program in the setup screen (`utils/programLink.ts`).

### Deployment
Two Vercel projects deploy from `main`: the frontend (served at `https://aubg-advisor.com`) and the backend (a `*.vercel.app` URL, which `VITE_API_BASE` points at).
- CORS: `main.py` allows localhost and any `https://*.vercel.app` origin; custom domains must be listed in the backend's `CORS_ORIGINS`. Env vars are read at import, so changing one needs a backend redeploy.
- Vercel installs the backend with `uv` from `requirements.txt`; unpinned transitive deps (e.g. `multidict` via `supabase`) can break a build when an upstream release is published only partially, and redeploying later fixes it.
- `vercel.json` exists at the repo root and in `frontend/` with the same content (`/p/:token` rewrite, `X-Robots-Tag: noindex` on `/p/*` shared plans); keep them in sync.
- Homepage SEO lives in `frontend/index.html` (meta/Open Graph tags and JSON-LD with absolute `https://aubg-advisor.com` URLs, plus crawler-visible copy inside `#root` that React replaces on mount) and `frontend/public/` (favicons, `og-image.png`, `site.webmanifest`, `robots.txt`, `llms.txt`). Those absolute URLs, and the ones in `scripts/seo-pages.mjs`, need updating if the domain changes.

## Testing gotchas
- Every test class derives from `tests/_isolation.IsolatedTestCase`. `excel_course_catalog` keeps a module-global course index that the engine and transcript import fall back to; each test starts from an empty index (`excel_index = "empty"`, synthetic catalogs) or the shipped one (`excel_index = "real"`) and gets the previous state restored afterwards. Use it for new test classes.
- `generate_plan` clamps any start term earlier than today's term to the current term (`_current_start_term` uses `date.today()`). Patch `degree_engine._current_start_term` when term labels matter (the scenario tests do).
- `degree_total_credits` only applies when the catalog sets it, so synthetic catalogs are not topped up to 120 credits; likewise the academic policies (residency, course load, independent study) need `enforce_academic_policies: true`.
- Importing `main` imports the Supabase SDK at module load.
